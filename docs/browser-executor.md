# Browser research: measured default and local-executor experiment

**Status: not activated.** The tested choice for the Browser agent is **text-only Camofox snapshots plus a scoped native `SELECT` tool**, with the large `openai/gpt-6-luna` model at low thinking. The local `browser_execute` decision sidecar is an **opt-in experiment, disabled by default** (`flake.nix`, `localBrowserExecutorEnabled = false`). Earlier local rounds sometimes used fewer large-model tokens but had lower or uncertain completion; **matched final-core repeats did not save total large-model tokens over the strong control** and passed fewer tasks. Do not switch or download a model merely to read this report.

This is an engineering decision about *these implementations and test conditions*, not a claim that browser-specific or local models cannot work. An owner must separately decide whether to commit and activate configuration; nothing in this document authorizes a switch.

## Evidence and recomputation

`packages/browser-executor/bench/results/measurements.jsonl` holds **563 allowlisted per-task records in 37 separately labeled suites**. This includes the original 401 records plus **four paired 30-task final-core rounds**, twelve final public-read-only records, and thirty from a **discarded compact-snapshot trial**. `manifest.json` describes provenance, frozen fixture hashes, final-core hashes and the compact plugin hash; `memory.json` records separate offline resource probes. Early historical experiments did not save per-run source hashes: their `historical_code_sha256` remains `null`, *not* today's implementation misrepresented as old code. The final30task results ran the historical frozen core with SHA256 **`584667fd1d4cfa7ae25b5d1242039843d8b7456c6b0445a0a0fcd0fd52bd52a9`**; this is retained as historical provenance, not the current core. After those benchmarks, security guards were added, followed by a safety-only guard blocking Submit in payment/payment-context cases. The current `core.mjs` SHA256 is **`01f3f3f975985f41f85259c56e56c9972a33626fb629450b360ef9c8e17c5f65`**. Revised guard-only code was tested for concurrent tools, but **was not rebenchmarked on the 30-task suite**. The optional-only guard does not change the production default, which remains text-only snapshots plus native `SELECT`; that path does not enable the optional guarded executor. Bridge and plugin SHA256 also agree with the final frozen report. **The archived `camofox.mjs` digest is truncated and disagrees with the currently verified file**; do not claim that transport file is proven identical across those historical runs. The compact plugin was temporary and its production change was discarded; its SHA256 is separate. There are no session IDs, host paths, oracle keys, authentication data, private URLs, prompts, snapshots or model responses in these files.

Recompute all arm/category/split aggregates and a paired comparison with Python's standard library:

```sh
devenv shell -- python3 packages/browser-executor/bench/analyze.py \
  --pair original-text native-select-control-first \
  --pair final-control-a final-laya-a \
  --pair final-control-b final-laya-b \
  --pair final-control-a compact-calibration-discarded \
  --pair final-control-a compact-heldout-discarded \
  --output /tmp/browser-benchmark-analysis.json
devenv shell -- python3 -m unittest discover -s packages/browser-executor/bench -p test_run.py
devenv shell -- node --test packages/browser-executor/bench/server.test.js
```

The analyzer reports **per-task wall mean, observed p50/p95, Wilson 95% pass-rate intervals and paired pass transitions**. These are descriptive uncertainty summaries on a small, related sample—not independent-site confidence guarantees. For the local bridge its p50/p95 pools only recorded per-call `latency_ms` samples; end-to-end wall time additionally includes tool/network/model/workspace setup. `model_input_plus_cache` is the sum of uncached input and cache reads across turns, **not** the final prompt size or a subscription bill. RSS is a sampled process metric; Camofox health RSS is its server process, not the entire browser VM or combined host memory.

Those layouts were already observed; this is not an independent heldout test.

The original Camofox 1.15.0 upstream tool requests `includeScreenshot=true` for `camofox_snapshot` and splits the returned screenshot into an image block (`mcp/lib/tool-contracts.mjs:265,469-477`). Excluding the dedicated screenshot *tool* did not exclude screenshot *blocks*: **105 images from 108 original snapshots**, versus **0/108** text-only. Large-model total input + cache read fell about **7.9×**, and mean per-task maximum prompt fell about **12×**, **without quality loss** (18/30 in each). This is the major context improvement; the final local hybrid's later smaller exposed-snapshot count must not be confused with another tenfold improvement. The strong control adds a safe, scoped observed-ref/option tool **and prepared-value guidance that was not present in the original frozen text-only arm**. It jumps from 18 to 27 passes on its first 30-task run; do not attribute all nine additional passes to SELECT alone. In this fixture the long form's native dropdown and login filter were common failures without usable selection.

The **matched final-core** A/B pairs use the same prepared-value prompt, text-only snapshots, and native SELECT. Laya's conservative `.5/.05`, history-two, eight-step policy logged **171 local actions across the two 30-task runs** (88 + 83) and exposed fewer large-model snapshots (108/100 versus 120/122). Yet the large-model token totals were **higher**, not lower: A **2.695M vs control 2.285M** (+18.0%), B **2.381M vs 2.316M** (+2.8%), with **25 vs 26** and **25 vs 27** oracle passes and longer wall times in both pairs. The recorded escalations/checkpoints and extra tool/history traffic are plausible contributors; the aggregates alone do **not** establish a causal attribution without matching traces. The tradeoff is not Pareto-superior: the local path did not reduce context demand relative to the strong control *or* preserve completion on these runs. A user might accept up to **10 percentage points** less completion **if** it bought **more than 10× incremental context savings** over an otherwise matched strong control; this is an explicit illustrative decision threshold, **not an observed result or guaranteed safety allowance**. Neither final pair came close to that context saving. The ~8× benefit over the *original screenshot arm* was already achieved **without** a local model.

Earlier Laya hybrid results **24/30 and 25/30** versus strong-control repeats **25/30 and 27/30** sometimes used fewer tokens, but reflect older code and policies. Kev was competitive on its early suite. The tested local policies were changed after examining calibration *and* the originally called heldout split, so later full replays—including the final frozen-code comparison—are **not fresh heldout**. The separate ten-case generated-data challenge changed names, decoys and dates while keeping the same layouts: **control 9/10, Laya 8/10**, again not unseen UI. Do not cherry-pick the first 27/30 or interpret calibrated-looking confidence values as actual safety probabilities. The fixture's 10 calibration and 20 heldout tasks reuse the same seven layouts (`packages/browser-executor/bench/tasks.js:1-85`). All 16 long-form values are explicitly in the goal; no oracle values were supplied to the agent.

Six separate **read-only public-web tasks** on [Books to Scrape](https://books.toscrape.com/), [Quotes to Scrape](https://quotes.toscrape.com/) and [Wikipedia](https://en.wikipedia.org/) were independently checked against final URL paths, not against a synthetic oracle. The *earlier* control passed **5/6** and Laya **4/6**; the **final-code** control and Laya each passed **4/6**. Strict path matching rejected canonical equivalents `/tag/love/page/1/` or `/tag/humor/page/1/` where `/tag/love/` or `/tag/humor/` was required; keep those strict misses recorded, not silently re-score them. The final `wiki-ada` tab creation was denied by browser admission in **both** arms, not a demonstrated model-navigation failure. These six tasks had no logins, purchases or account operations, and do not establish broad real-web reliability.

### Mistakes, loops, latency and memory

`wrong_actions` counts only oracle-invalid submissions plus decoy detail views; it is a **lower bound** on wrong tool behavior, not an error-rate denominator for all actions. Many failures stop before any submission. The original image arm recorded 4 wrong actions over 320 Camofox actions; its text-only counterpart 1/310. The first SELECT control recorded zero, while the early Kev hybrid recorded two. `observed_action_loops` counts only explicit `action_loop` executor results (one in the early Kev suite); absent loop telemetry is **not evidence of zero repeated or cyclic agent actions**. Per-task recovery after invalid submissions and local escalation/checkpoint reasons remain distinguished in the evidence; a model saying “done” is not the oracle.

Per-call local decision latency from published event samples: **Kev first hybrid p50/p95 260/359 ms**, **Laya first hybrid 188/354 ms**, later Laya B **114/232 ms**; matched final Laya A **177/274 ms** and B **162/251 ms**. Local decisions are not end-to-end page/task latency. Mean task wall time is in the table. Timeout, budget-hit, and unavailable-oracle counters are independently reported by `analyze.py`. Small-n and changing prompts/policies prevent causal performance claims beyond the paired controls.

Stock Laya v17s (approximately **644 MiB** artifact) under native `laya-mlx` **0.2.0 / MLX 0.32.2** matched the official recorded native operation/target sample; an offline 144-decision authored probe scored **89/144 joint exact, p50/p95 124/161 ms**. The locally merged 4-bit generic Kev is approximately **404 MiB** on disk. An earlier Torch 2.6 MPS failure was a **runtime/format issue**: Torch 2.11 MPS matched MLX's top operation and target on twelve small cases. The **uncapped MLX allocator cache reached about 10.9 GiB**, with swap exceeding 8 GiB. A cache-capped rerun (~256–261 MiB cache) held about 614 MiB active MLX, with ~1,103 MiB sampled RSS and ~1,557 MiB observed peak. A separate four-decision packaged-worker `ps` sample was **599 MiB RSS for Kev, 1,097 MiB for Laya** (`results/memory.json`); this is not an inference peak guarantee. Do not use the uncapped configuration or run concurrent resident models on this evidence. CoreML and ONNX were **not measured** here.

Model/runtime provenance: [stock Laya browser](https://huggingface.co/cklxx/laya-browser), [laya-mlx](https://github.com/mizorewww/laya-mlx), [Kev 0.8B adapter](https://huggingface.co/jaredpalmer/kev-0.8b), [Qwen3.5-0.8B Base](https://huggingface.co/Qwen/Qwen3.5-0.8B-Base), and [browser-trained Kev 0.6B](https://huggingface.co/arbazsiddiqui/kev-0.6b-browser-use). The generic Kev-0.8B and browser-trained Kev-0.6B are distinct checkpoints; the latter's separate offline joint probe scored 43/60, not a browser rollout result. Pinned source revisions and versions are in `results/manifest.json` and `packages/browser-decision.nix:103-180`. Neither this evidence nor the default configuration downloads a model or starts the sidecar; explicitly enabling/building the experimental package may fetch the pinned model artifacts.

## Reusable harness (future evidence, not bootstrap)

`packages/browser-executor/bench/run.py` is a repeated-task evaluation runner, **not** a one-time setup or production activation script. It requires an explicit direct OpenClaw executable, a JSON file containing **only a public model catalog**, explicit provider/model, a pinned plugin directory with a manifest, and a *new private output directory outside the public repository*. It rejects channel/live configuration and unknown model-row fields. It uses a new OpenClaw state, home, workspace, agent session, task run ID and 0700 directory per attempt; no messaging delivery or ambient agent session. It launches its **own disposable Camofox image** (no pull) with a read-only fixture mount, new random Camofox access key, and host-loopback-only published ports. The *separate* fixture oracle key stays in the runner process; all new output records are allowlisted metrics with no raw transcript. Optional `--trace-synthetic` keeps a compact, redacted tool/fixture snapshot excerpt under the private output, never image bytes. Credential DB and container cleanup are mandatory even after timeouts; scoped own-tab cleanup is best-effort while that container runs, and container termination removes remaining tabs. Browser tool-call budgets are 35/300 seconds or 75/600 seconds for long tasks, polled at one-second resolution rather than enforced synchronously inside each action.

Use the direct packaged executable, **not** a user CLI wrapper that injects a live Gateway token. Example (substitute your locally available paths and model catalog; no secrets in this command):

```sh
devenv shell -- python3 packages/browser-executor/bench/run.py \
  --openclaw /path/to/direct/openclaw \
  --config /path/to/public-model-catalog.json \
  --model openai/example-model \
  --plugin-path /path/to/pinned-camofox-plugin \
  --auth-env OPENAI_API_KEY \
  --suite independent-recheck \
  --output /path/to/new-private-temp-results
```

`--auth-env NAME` is the default credential mode: **only explicitly named provider variables** reach the isolated agent, along with a newly generated Camofox key. The tool uses pinned `--config` with a fresh `HOME`/`--state-dir`; OpenClaw 2026.9.4 does **not** permit combining `--config` and its CLI `--auth-env-only` flag, so it runs `--no-auth-env-only` with no ambient account home/store. An API key must be valid for the chosen model's actual route—**an API key is not interchangeable with the tested ChatGPT subscription/OAuth route**. For that route, explicitly opt in to `--auth-profile-file /path/to/owned-0600.json`, containing only `provider`, current `access`, millisecond `expires`, and `accountId` (never a refresh token). The access token is transiently installed in a task-local DB and unlinked afterward; the runner never reads a live login path or refreshes it. Keep the input file private and remove it yourself when finished. The historical results used this access-only route, not a default environment API key.

For a native-SELECT control, choose a plugin declaring `camofox_select` and append `--extra-tool camofox_select`, with a prompt template that says to use it. For an opt-in hybrid, select a plugin declaring `browser_execute`, append `--extra-tool browser_execute --executor-backend laya` (or `kev`), and supply a corresponding non-production prompt template. `--model-executable` only passes `BROWSER_DECISION_EXECUTABLE` for **plugin variants that explicitly consume it**; the Nix-built wrapper embeds its executable instead. The runner neither substitutes a different model behind that wrapper nor claims the argument overrides its compiled backend. `--prompt-template-file` supports only `{goal}`, `{start_url}`, `{variables}`; controls and hybrids must receive matching prepared-value instructions for a fair comparison. Save independent repetitions as separate suites and keep tuning/calibration outside any clean challenge set.

**Differences from live:** the original production Camofox Squid proxy refused private `host.containers.internal` fixture URLs, so these runs used an isolated, proxy-free Camofox container. The harness also disables the Browser agent's Podman sandbox and fallbacks, and does not exercise its messaging/delegation ingress. These results support the default feature choice in this synthetic setting; they do **not** certify live browser safety, credential handling on other sites, or arbitrary web workflows.
